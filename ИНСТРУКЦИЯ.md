# Подключение эмулятора Честного Знака к 1С

Эмулятор подменяет для 1С серверы ЧЗ (ГИС МТ, СУЗ, Национальный каталог). Конфигурацию 1С не меняем:
1С ходит в ЧЗ как обычно, только через прокси-сервер эмулятора. Проверено на КА 2.5.27.93.

Понадобится: Windows и права настроить базу 1С. Python не нужен — эмулятор собран в один файл.

Комплект: `chz-emulator.exe`, эта инструкция, расширение `ЧЗ_БезПодписи.cfe`.

---

## Шаг 1. Запустить эмулятор

Положите `chz-emulator.exe` в отдельную папку и запустите. Откроется консольное окно и браузер
с интерфейсом эмулятора: http://127.0.0.1:3128/. Рядом с exe появится папка `data`: база эмулятора,
журнал и сертификаты.

Окно эмулятора не закрывайте, пока работаете с 1С. Порт занят — значит, эмулятор уже запущен.

Ключи запуска: `--port 3128`, `--bind 0.0.0.0` (пустить 1С с других компьютеров — тогда в шаге 3
вместо `127.0.0.1` укажите адрес компьютера с эмулятором), `--no-browser`, `--data <папка>`.
Из исходников то же самое: `start.bat` или `python chz_emulator.py`.

## Шаг 2. Доверить сертификат эмулятора (один раз)

1С проверяет HTTPS-сертификат сервера. Эмулятор выдаёт свой, поэтому его корневой сертификат
нужно добавить в доверенные на компьютере, где работает **сервер** 1С:
- файловая база — на компьютере пользователя;
- клиент-серверная — на сервере 1С.

Сертификат: `data\certs\ca.crt` (он же — ссылка «Скачать корневой сертификат» на вкладке «Действия»).

**Для текущего пользователя** (файловая база):
```
certutil -user -addstore Root "<папка эмулятора>\data\certs\ca.crt"
```
Windows покажет предупреждение о безопасности — нажмите «Да».

**Для всего компьютера** (сервер 1С работает под служебной учётной записью), из командной строки
от имени администратора:
```
certutil -addstore Root "<папка эмулятора>\data\certs\ca.crt"
```

Сертификат называется «CHZ Emulator Root CA». Удалить его потом можно через `certmgr.msc` →
«Доверенные корневые центры сертификации».

## Шаг 3. Настроить базу 1С

Все пункты ниже — в разделе **«НСИ и администрирование»**.

1. **Тестовый контур ИС МП.** НСИ и администрирование → Настройка интеграции →
   **Интеграция с ИС МП (обувь, одежда, табак...)** → откроется «Настройки маркировки (Честный Знак)» →
   вкладка **«Электронные подписи и авторизация»** → флажок **«Тестовый контур»**.
   Эмулятор перехватывает и боевые адреса ЧЗ, но тестовый контур нужен: в нём работает расширение
   без подписи (шаг 4), а СУЗ подключается без сервиса 1С:БИП.

2. **Прокси-сервер.** Где задаётся, зависит от вида базы:
   - **файловая база** — НСИ и администрирование → Сервис → **Персональные настройки** («Мои настройки») →
     ссылка **«Настройка доступа к Интернету»**. Настройка своя у каждого пользователя: задать её надо
     каждому, кто работает с ЧЗ;
   - **клиент-серверная** — НСИ и администрирование → Администрирование → **Общие настройки** →
     «Параметры прокси-сервера» (настройка на сервере 1С, общая для всех).

   В форме: «Использовать прокси-сервер» — включить, системные настройки — не использовать; адрес
   `127.0.0.1`, порт `3128`; «Не использовать прокси для локальных адресов» — выключить.

   Задавайте в **тонком или толстом клиенте**: веб-клиент эту форму не открывает
   («в веб-клиенте параметры прокси-сервера необходимо задавать в настройках браузера»).
   Внимание: прокси действует на все интернет-запросы базы. Остальные адреса эмулятор пропускает
   насквозь, но если эмулятор не запущен, у 1С пропадёт интернет. На рабочей базе прокси не включайте.

3. **СУЗ** (если заказываете коды): в настройках станции управления заказами укажите
   адрес `suz.sandbox.crptech.ru`, порт `443`, защищённое соединение, идентификатор СУЗ (omsId) — любой.

4. **Учёт маркируемой продукции** должен быть включён, а нужные товарные группы отмечены
   (обычная настройка ИС МП). У номенклатуры должен быть GTIN (штрихкод) — по нему 1С узнаёт товар в коде.

## Шаг 4. Расширение «ЧЗ_БезПодписи» (если нет ЭП)

Без электронной подписи (КриптоПро + сертификат) 1С не получит токен ЧЗ и не отправит документы.
Для разработки есть расширение `extension\ЧЗ_БезПодписи.cfe` (ссылка на вкладке «Действия»):
вместо подписи оно подставляет заглушку. Эмулятор подпись не проверяет.

- Работает **только при включённом «Тестовом контуре» ИС МП**. С выключенным контуром ничего не меняет.
- Настоящий ЧЗ заглушку не примет. На рабочие базы расширение не ставить.

Подключение: НСИ и администрирование → Администрирование → Печатные формы, отчёты и обработки → **Расширения** →
«Добавить из файла» → `ЧЗ_БезПодписи.cfe`. В списке оно называется «ЧЗ: без подписи (только тестовый контур)». Затем в свойствах расширения **снимите флажок
«Безопасный режим»** — иначе перехват не сработает. Перезапустите 1С.

Через конфигуратор: Конфигурация → Расширения конфигурации → Добавить → Загрузить из файла.

## Шаг 5. Проверить

1. В эмуляторе откройте вкладку **«Автосценарий»** и нажмите «Запустить» — все шаги должны быть OK.
   Это проверка самого эмулятора, без 1С.
2. В 1С выполните любое действие с ЧЗ, например «Обмен с ИС МП» или проверку кода маркировки.
3. На вкладке **«Журнал»** эмулятора должны появиться запросы от 1С.

## Тестовые данные

- **Национальный каталог** — вкладка «Нац. каталог»: карточки товаров (GTIN, наименование, товарная группа,
  ТН ВЭД, бренд, ИНН, статус). Карточку можно добавить вручную, изменить (щёлкнуть строку) или загрузить
  списком: вставить строки из Excel или CSV в поле «Импорт». По карточке ЧЗ отвечает 1С, что это за товар.
  GTIN без карточки ЧЗ «не знает», как и настоящий.
  Сопоставление с номенклатурой 1С идёт по GTIN в штрихкодах номенклатуры, поэтому GTIN в 1С и в каталоге
  должен совпадать.

- **Коды маркировки** — вкладка «Действия» → «Сгенерировать коды»: GTIN, товарная группа,
  количество, статус (в обороте / нанесён / эмитирован), владелец (ИНН вашей организации), можно сразу в короб.
- **Входящая отгрузка от поставщика** (для приёмки в 1С) — вкладка «Действия» →
  «Входящая отгрузка»: у вашей организации появится входящий документ «Ожидает приёмки».
- Карточка НК создаётся и автоматически: при генерации кодов и при заказе кодов в СУЗ (если в настройках
  не включено «СУЗ требует карточку НК»).
- **Ошибки** — вкладка «Настройки»: «Отклонять все документы», «Отказывать в авторизации»,
  задержки обработки.

## Стенд KA99 (готовая база для проверки)

База `H:\1C_Стенд\KA99` (КА 2.5.27.93) уже настроена под эмулятор: тестовый контур, прокси 127.0.0.1:3128,
учёт обуви, расширение «ЧЗ_БезПодписи» без безопасного режима.

| Что | Значение |
|---|---|
| Организация | ООО Тест ЧЗ, ИНН 7701234567, КПП 770101001 |
| Подразделение | Тестовое подразделение |
| Пользователь | Тест («Тестовый пользователь»), пароль пустой, полные права (группа доступа «Администраторы») |
| Веб-клиент | http://localhost:8081/ka99 (Apache) |

## Если не работает

| Признак | Причина и что сделать |
|---|---|
| В «Журнале» эмулятора пусто | 1С не идёт через прокси: проверьте шаг 3.2 и что эмулятор запущен. В файловой базе настройка прокси — у каждого пользователя своя. |
| В журнале строка «TLS не установлен» | Сертификат не доверен на компьютере сервера 1С (шаг 2). |
| 1С пишет «Метод не реализован в эмуляторе» (404) | Этот метод ЧЗ эмулятор пока не поддерживает. Адрес видно в журнале — сообщите разработчику. |
| В журнале нет запросов от веб-клиента | Прокси для веб-клиента задаётся в настройках браузера, а запросы к ЧЗ идут с сервера (Apache) — ему нужен прокси пользователя, под которым он входит. Проще проверять в тонком клиенте. |
| 1С просит подписать / выбрать сертификат | Не подключено расширение, не снят «Безопасный режим» или выключен «Тестовый контур» (шаг 4). |
| Код маркировки «не найден» | Кода нет в эмуляторе — создайте его на вкладке «Действия» или включите в настройках «Неизвестные коды: auto». |
| Документ «Ошибка» с текстом про статус или владельца | Это проверка эмулятора, как у ЧЗ. Проверьте статус кода на вкладке «Коды» или выключите «Строгую проверку». |
